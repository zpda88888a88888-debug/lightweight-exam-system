# UI / UX 设计规范

> 适用范围：考生端（手机）与管理端（桌面）。
> 本文档约束"长什么样、怎么反馈、文案怎么写"，与 `规格说明.md`（做什么）互补。
> 新增界面或修改交互前先读本文档；本文档与规格冲突时以规格为准，并回来修订本文档。

---

## 1. 总体原则

1. **考生端面向手机、单手可操作**：单列布局、大点击区域（≥ 44px）、字号不小于 14px。
   考生是在考场低头看手机，不是坐在电脑前。
2. **管理端面向桌面、信息密度优先**：侧边导航 + 表格，一屏尽量多放信息。
3. **状态永远可见**：当前处于什么状态（草稿/进行中/已结束）、能不能操作、为什么不能，
   必须写在界面上，而不是让管理员点一下才知道被拒绝。
4. **危险与不可逆操作必须二次确认**，并在确认文案里说清后果。
5. **文案用业务语言**，不用技术术语。对管理员说"发布后名单和试卷都会冻结"，
   而不是"status 将变为 published"。

## 2. 考生端

### 2.1 页面结构

| 页面 | 内容 |
|---|---|
| 登录 | 手机号 + 邀请码；错误信息直接展示后端返回的中文原因 |
| 等待 | 考试名称、开考时间、截止时间、距开考倒计时；到点后"开始考试"可点 |
| 答题 | 顶部固定栏（考试名 / 已答进度 / 倒计时 / 答题卡 / 交卷）+ 一页到底题目列表 |
| 完成 | 交卷成功；**不显示分数**（成绩由管理员线下告知） |

### 2.2 选项展示（重点）

**规则：显示标号按显示位置依次为 A、B、C、D…**

考生看到的永远是：

```
A  安全第一、预防为主、综合治理
B  生产第一、安全第二
C  效益优先、安全兼顾
D  先生产、后安全
```

而不是：

```
B  生产第一、安全第二
A  安全第一、预防为主、综合治理      ← 不允许出现这种"标号乱序"
```

**原因**：选项内容按考生独立乱序（防抄答案）是业务要求，但把**标号**也打乱
只会让考生困惑，不会增加任何防作弊价值——因为旁边的考生看到的可能是另一种排列，
标号本身并不承载信息。

**实现约定**：标号 = 显示位置（第 1 项 → A，第 2 项 → B …），
内部仍持有服务端返回的**原始选项标识**；提交时按显示位置映射回原始标识。
服务端判分只认原始标识。

判断题不打乱，固定"对 / 错"。

### 2.3 倒计时

- 位置：顶部固定栏右侧，进入答题页后始终可见。
- 依据：服务端 `end_at`（统一截止时间），不是"进入时刻 + 时长"。
- 剩余 ≤ 5 分钟变红并轻微呼吸闪烁，提示紧迫但不打断答题。
- 到点自动交卷，**不再弹确认框**（考生已经被告知"到点自动交卷"）。

### 2.4 答案保存反馈

- 每次选择立即写入 IndexedDB（不防抖，见设计决策文档）。
- 顶部显示"已保存 HH:MM:SS"的轻量提示；保存失败显示"本地保存失败"。
- 保存失败**不阻断**答题：答案仍在内存里，交卷照常提交。

### 2.5 答题卡

- 网格展示题号，**已答为实心主色**、未答为浅底。
- 顶部显示"已答 X / N"。
- 点击题号滚动定位到该题并关闭答题卡。
- 移动端以浮层呈现。

### 2.6 交卷

- 提前交卷必须弹确认框，并明确告知未答题数：
  "还有 **X** 题未答，交卷后不可再修改。"
- 全部作答时文案为"题目已全部作答，交卷后不可再修改。"
- 提交失败：保留答案 + 显示"重试提交"按钮 + 说明"答案已保存在本机"。

## 3. 管理端

### 3.1 导航结构

```
考试管理    考试列表与查询、建/改/删草稿、发布、归档、查看成绩与统计
考生管理    按「考试场次」管理名单与邀请码（发布前的准备工作）
试卷管理    查看每场考试的试卷快照（只读）
题库管理    题目增删改查、筛选、JSON 批量导入、题目统计
```

**职责边界（重要）**：同一个功能只在一个地方有入口，避免"两处都能改、互相同步"。

| 事项 | 归属 | 理由 |
|---|---|---|
| 名单导入、生成/导出邀请码 | 考生管理 | 都是**发布前**的准备动作，且按场次组织 |
| 成绩、及格率、题目标错率 | 考试管理 → 详情 | 考完才有数据 |
| 试卷题目清单 | 试卷管理 | 只读快照 |
| 题目本身与题目统计 | 题库管理 | 与考试无关的题库属性 |

跨模块跳转要**带上上下文**：考试管理草稿行的「名单与邀请码」跳到考生管理时，
通过 `?exam=<id>` 预先选中该场次，管理员不需要再选一次。

### 3.2 状态徽标

用颜色 + 中文区分考试状态，禁止只给颜色不给文字（色盲可用性）：

| 状态 | 文案 | 色调 |
|---|---|---|
| `draft` | 草稿 | 中性灰 |
| `upcoming` | 未开始 | 橙（等待） |
| `running` | 进行中 | 绿（可用） |
| `ended` | 已结束 | 浅灰（失效） |
| `archived` | 已归档 | 紫（封存） |

### 3.3 表单规范

1. **封闭选项优先**：能从已有数据里选的，不让用户手打。
   - 组卷规则的**标签**必须从题库已有标签中下拉选择，并显示"可用 N 题"。
   - 手打标签极易产生"安全生产 "（多空格）这类错别字，导致发布时题量不足。
2. **即时校验优于事后报错**：抽题数超过该标签可用题数时，输入框当场提示，
   而不是等到点"发布"才失败。
3. **字段旁给出口径说明**：凡是"口径类"字段（及格比例、判分规则相关）都要有说明文案。
4. 错误信息展示在后端返回的位置（表单顶部 / 字段下方），文案直接用后端的中文原因。

### 3.4 及格比例字段的说明文案（规格强制）

```
及格比例
[ 60% ▾ ]
ℹ 按得分排名取前 60% 为及格；同分并列者全部通过（实际及格人数可能多于 60%）；
  分母为已交卷人数，缺考不计入。
```

### 3.5 危险操作与二次确认

| 操作 | 确认文案要点 |
|---|---|
| 发布考试 | 说明"将随机抽题生成快照，名单/组卷/时间全部冻结" |
| 重新生成邀请码 | 说明"会覆盖全部邀请码，旧码立即失效，已分发的需重新发放" |
| 删除草稿考试 | 说明"不可恢复" |
| 归档考试 | 说明归档后不可再修改 |
| 删除题目 | 提示已被已发布考试引用的题目会被拒绝 |

### 3.6 查询表单规范

- 条件以**一行横向排列**放在列表上方，最后一列放「查询」；有任一条件生效时额外显示「清除」。
- 只标了"模糊"的字段才做包含匹配（名称）；编号类字段做包含匹配便于"记得一半"的场景。
- 日期范围用两个 `<input type="date">`（起、止），起止都填时按闭区间过滤。
- **空条件不下发**：前端把未填写的条件转为 `undefined`，后端也把空串当作"不过滤"，
  避免"打开页面列表是空的"这种诡异现象。
- **空态要能区分**：没有数据 vs 查询无结果。后者必须提供「清除查询条件」入口。
- 查询条件变化时同步到地址栏（`?exam=`、查询参数），刷新后可复现同一视图。

### 3.7 统计展示规范

- 百分比统一保留 1 位小数，并**同时给出样本量**（如 `75%（6/8）`）。
  只有百分比没有样本量时，2/2 和 200/200 看起来一样可信。
- **"没有数据"必须与"数值为 0"区分开**：
  从未被抽中、从未被作答 → 显示「暂无」；
  确实做过且全错 → 显示 `0%`。
  这两者混淆会让管理员误判题目难度。
- 时间列展示为本地可读格式（`YYYY-MM-DD HH:MM`），不直接展示 ISO 串。
- **状态标签带人数**：状态筛选项直接显示 `未登录 3`、`答题中 1`，
  点一下就能看到具体是谁，不用先去翻表格数人头。
- **人数汇总基于全量数据**，不随筛选变化。否则"未登录 0 人"会因为
  当前筛了"已交卷"而显得自相矛盾。

### 3.8 空态 / 加载 / 错误

- **空态**：说明"为什么空"和"下一步做什么"，例如
  "暂无题目，请先新增或批量导入"，而不是只有"暂无数据"。
- **加载中**：表格区域显示"加载中…"，不要留白。
- **错误**：顶部红色 Alert，保留用户已填内容，不清空表单。

---

### 3.9 关联对象的选择（场次选择器）

当模块需要"先选一个业务对象再操作"时（例如考生管理要先选考试场次）：

- **候选超过一屏就不要用下拉框**。下拉框既看不到状态、时间等关键字段，
  也无法筛选；场次一多基本没法用。
- **改用「查询条件 + 可点击结果列表」**：条件与对应列表页保持一致（管理员已经熟悉那套筛选），
  结果用表格呈现（名称 / 编号 / 状态 / 时间），点一行即选中，当前选中行高亮。
- **选中后收起选择器**，改为一行"已选：<对象信息> + [更换场次]"。
  这样页面的重心始终在"对选中对象的操作"上，而不是选择器本身。
- 结果列表限高可滚动，避免把下方操作区挤到屏幕外。
- 没有任何候选时，空态要指向"去哪里创建"，而不是干说"暂无数据"。

## 4. 文案规范

| 场景 | 用 | 不用 |
|---|---|---|
| 考生身份 | 考生 | 用户、账号 |
| 场次 | 考试 | 考场、任务 |
| 发布后状态 | 已冻结 / 不可修改 | 锁定、只读 |
| 及格线口径 | 同分并列者全部通过 | 并列全通过（口语化不足） |
| 缺考 | 缺考 | 未参加、缺席 |
| 题目内容 | 题干、选项 | 标题、答案项 |

- 中文标点用全角（，。；：），数字与英文用半角。
- 界面文案不出现技术术语（如 `attempt`、`status`、`payload`）。

---

## 5. 视觉与响应式

- 主色 `#2563eb`（蓝，用于主按钮、已选、进度）；成功 `#16a34a`；危险 `#dc2626`；警示 `#d97706`。
- 圆角 10px，卡片 1px 边框 + 轻阴影，避免重装饰。
- 考生端断点：< 600px 单列；表格类信息在窄屏改为卡片堆叠或横向滚动。
- 管理端 < 980px 时图表由两列降为单列。

---

## 6. 可访问性最低要求

- 所有表单控件都有 `<label>`（`for` 关联），不依赖 placeholder 充当标签。
- 状态不只靠颜色传达，必须同时有文字。
- 模态框打开后焦点进入框内，Esc 或点击遮罩可关闭。
- 表格表头 `<th>` 语义正确。
